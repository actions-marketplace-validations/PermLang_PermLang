# Maintainers

Who maintains PermLang, and the accounts and access each one holds. How people
become maintainers, and how access is reviewed, is in
[GOVERNANCE.md](GOVERNANCE.md).

| Maintainer | GitHub | Since |
| --- | --- | --- |
| Aaron | [@parkwebdev](https://github.com/parkwebdev) | 2026 (the project's creator) |

## Access to the project's resources

| Resource | What it can do | Who has it |
| --- | --- | --- |
| [PermLang GitHub organization](https://github.com/PermLang) | Owner: every repository, settings, branch protection, security advisories | @parkwebdev |
| [npm package `permlang`](https://www.npmjs.com/package/permlang) and the `permlang` npm organization | Owner. Releases are published by the release workflow through npm's trusted publishing; no person or token publishes them | @parkwebdev (npm user `parkweb`) |
| [Codecov](https://app.codecov.io/gh/PermLang/PermLang) | Coverage reports and settings | @parkwebdev |
| [OpenSSF Best Practices project](https://www.bestpractices.dev/projects/15173) | Edit the project's answers | @parkwebdev |

Every account above uses two-factor authentication. No secret for any of them is
stored in the repository or in GitHub Actions ([docs/policies.md](docs/policies.md#secrets-and-credentials)).

## Contact

- **A security problem:** report it privately, as [SECURITY.md](SECURITY.md)
  describes.
- **Conduct:** see [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
- **Anything else:** an [issue](https://github.com/PermLang/PermLang/issues) or a
  [discussion](https://github.com/PermLang/PermLang/discussions).

## Succession

There's no second maintainer yet, so nobody else holds these accounts, and
nobody is named to take them over. That's the project's biggest single risk,
and the first item on the [roadmap](ROADMAP.md).
