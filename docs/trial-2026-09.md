# Real-world trial, September 2026

The plan for this trial was to run PermLang on production code and log every
false positive and false negative. With no in-house production project, the
trial used two open-source TypeScript apps that use the network, a database,
and secrets in production:

| Project | Stack | Files checked | Time |
| --- | --- | --- | --- |
| [Umami](https://github.com/umami-software/umami) @ `ec0ff50` | Next.js, Prisma 7, ClickHouse, Kafka, Redis | 1,372 | 22 s |
| [Ghostfolio](https://github.com/ghostfolio/ghostfolio) API @ `d85772d` | NestJS, Prisma, Stripe, Redis/Bull | 524 | 9 s |

Both ran at `--strictness sketch` through their own `tsconfig`. Dependencies were
installed with `--ignore-scripts`, so no project code ran. The only dependency
code run was `prisma generate` (approved separately), so the Prisma client types
exist as they would in a real build. File counts include the generated client.

## Results

| | Umami | Ghostfolio API |
| --- | --- | --- |
| Functions that reach something | 2,439 | 494 |
| Direct `db.read` / `db.write` uses | 59 / 95 | 79 / 63 |
| Tables (Prisma models) seen | 46 read/write capabilities, plus raw SQL | 35, plus raw SQL |
| Direct `env` reads | 205 (74 variables) | 15 |
| Direct `net` / `exec` / `fs.write` uses | 13 / 6 / 13 | 3 / 0 / 0 |
| PERM004 unverifiable (after fixes) | 15, from 11 origins | 15, from 1 origin |

## False positives found and fixed

Each became a regression fixture in `fixtures/m5/`.

1. **Computed calls on a `const` record** (Umami, `src/openapi/source-analysis.ts`).
   `const knownSchemas: Record<string, () => Schema> = { ... }; knownSchemas[name]()`
   was unverifiable because the `Record` type hides the members. The initializer
   lists them, so the checker now follows each one. Umami: 17 → 15 PERM004.
2. **`require()` with a harmless literal** (Ghostfolio, `require('fuse.js')`,
   `require('./cryptocurrencies.json')`). Every `require` was unverifiable.
   Now only a computed specifier, a capability-bearing Node built-in
   (`child_process`, `fs`, ...), or a package with an adapter is. Local files are
   followed like imports. Ghostfolio: 70 → 15 PERM004.
3. **Relative module augmentations read as package names** (`@types/lodash`
   declares `declare module "../index"`). These were reported as a package
   named `..`.
4. **Prose in doc comments parsed as tags** (PermLang's own source, found in M4).

## False negative found and fixed

5. **Prisma clients built with `$extends`** (Umami: `new PrismaClient().$extends(readReplicas(...))`).
   Extended clients type every model through Prisma's generic runtime types, so
   the declaration of `findMany` doesn't name the model. Only 13 of Umami's 62
   read-style Prisma calls were detected. The model is now taken from the call
   site (`client.user.findMany` → `db.read(user)`): 59 are detected, and the
   rest of the 62 text matches aren't all Prisma calls. Regression fixture:
   `fixtures/m5/fail/prisma-extended.ts`.

## True positives worth noting

- Ghostfolio `apps/api/src/helper/markdown-table.helper.ts`: `new Function(...)`
  builds code at runtime. This is exactly what PERM004 is for.
- Ghostfolio's market-data providers all go through a `FetchService` that calls
  `globalThis.fetch` with a runtime URL. Every provider is traced through it, and
  needs bare `net` because the hosts aren't static.
- Ghostfolio's Stripe calls (`this.stripe.checkout.sessions.create`) are caught
  by the Stripe adapter's default, on real code.
- A spot check of every direct network, process, and file-write finding (27)
  found no false positives.
- The remaining Umami PERM004s are genuinely unverifiable: `require()` of a
  computed path, `import()` of a computed URL, and test mocks that call through
  a function table passed in as a parameter.

## False negatives

1. **Prisma needs its generated client.** Without `prisma generate`, no database
   access is visible, because the model types don't exist. In CI, generate
   before running PermLang. Both generators work: the classic client in
   `node_modules` (Ghostfolio) and Prisma 7's generated TypeScript (Umami).
2. **Packages without adapters.** First-party code called into 78 (Umami) and 60
   (Ghostfolio) packages that have no adapter. Most are pure libraries (zod,
   date-fns, React, big.js) and need none. But several carry capabilities that
   PermLang currently trusts (listing them in every report):
   - network: `kafkajs`, `redis` / `@redis/client`, `@clickhouse/client`,
     `node-fetch`, `undici`, `yahoo-finance2`, `alphavantage`, `twitter-api-v2`,
     `google-spreadsheet`, `ai` / `@openrouter/ai-sdk-provider`, `bull`,
     `@keyv/redis`, `passport-openidconnect`
   - file system: `maxmind`, `tar`, `jszip`
3. **Configuration services.** NestJS apps read settings through a service
   (`ConfigService`, `envalid`). The underlying `process.env` read is found where
   it happens, but callers see a bare `env`, not the variable names.

## What this means for the review

- D1 (trusting unmapped packages) is the largest gap in practice. A report
  section listing capability-bearing packages without adapters, plus a strict
  mode that fails on them, would make it visible. So would more built-in
  adapters for the packages above.
- Sketch mode is usable on day one: under 30 seconds on 1,300 files, with no
  annotations needed.
- Precision on what *is* detected was high. The false positives were all in
  unverifiable-code detection, and each had a structural fix.

## Follow-up: making D1 visible

After the trial, every package PermLang sees called is now either mapped by an
adapter, declared pure (`adapters/pure.json`), or listed in the report and
warned about (PERM006). New built-in adapters cover the capability-bearing
packages above. Rerunning both projects:

| | Umami | Ghostfolio API |
| --- | --- | --- |
| Packages called with no adapter | 78 → 19 | 60 → 18 |
| Direct `net` uses detected | 13 → 48 | 3 → 33 |
| Direct `env` uses detected | 205 → 205 | 15 → 17 (`ConfigService`) |

The new network findings were spot-checked: Redis reads and writes, Kafka
sends, queue operations, tweets, and AI calls are all real. A few are
over-approximations, such as `kafka.producer()`, which creates a producer
without connecting, but the same code goes on to use the connection.

The packages still unmapped are mostly ones whose behavior depends on
configuration: Next.js, Express and NestJS server modules, caches, queues, auth
strategies, and build tools. They're reported, one warning each.
